# Session 53 — capture request (27 files, two stimuli)

## Why these

The blend axis is the best-conditioned instrument this project has — it produced session 51's
mutual validation and session 52's impossibility proof. **It currently exists at exactly one
operating point** (DRIVE noon / GRUNT cut / ATTACK flat), and its magnitude read carries a known
bias. These captures fix both: Set A makes the measurement unbiased, Sets B/C turn the pedal's own
switches into a pre-vs-post-clipper localiser, Set D pins the bleed level from the pot law instead
of taking it from the model.

## ⚠ Correction to what I said earlier

I asked for each sweep as one continuous take without stopping the recorder, to avoid per-take
timing drift. **Disregard that — it isn't needed.** The blend axis never reads phase from the
waveform: it recovers `theta` algebraically from magnitudes across BLEND positions
(`a3_blend_axis.py::unpack`). It is alignment-immune by construction, so ordinary one-file-per-
setting takes are fine, exactly as before. Sorry for the extra hoop.

## Set A — tone bank at the reference condition (5 files) ⭐ highest value

**Stimulus: `a3_tones_48k.wav`.** Reference settings, sweeping BLEND only.

This is the one that decides whether session 52's impossibility result is real. The existing
instrument reads band *energy*, which includes harmonic power, so the recovered magnitude is an
upper bound and the recovered phase is biased toward 90° — and the ~−38° "excess lead" that rules
out every causal linear post-clipper element is computed from that biased phase. A single tone per
band has no harmonic power inside the measurement, so both become exact. It also gives C3's size at
20–32 Hz properly for the first time (currently unmeasured to better than ~3 dB, and C3 is A3's
dominant term).

```
a3tones_blend-0700.wav      BLEND fully CCW
a3tones_blend-0930.wav
a3tones_blend-1200.wav
a3tones_blend-1430.wav
a3tones_blend-1700.wav      BLEND fully CW
```

## Set B — BLEND sweep at DRIVE min and max (7 files)

**Stimulus: `test_signal_48k.wav`.**

A post-clipper linear element multiplies the OD path identically at every drive — that is the
*entire* basis for session 50's "post-clipper only" conclusion, and it was inferred from a drive
solve now known to rail at five bands. Measuring the complex target on the good axis at three
drives tests it directly.

```
drive-0700_blend-0930_base-od.wav      DRIVE fully CCW
drive-0700_blend-1200_base-od.wav
drive-0700_blend-1430_base-od.wav

drive-1700_blend-0930_base-od.wav      DRIVE fully CW
drive-1700_blend-1200_base-od.wav
drive-1700_blend-1430_base-od.wav

drive-1700_blend-0700_base-od.wav      CONTROL — see below
```

The control matters: at BLEND=0 the wiper sits on the clean pin, so the OD path contributes nothing
and the capture *should* be identical to the existing `blend-0700_base-od.wav` regardless of DRIVE.
Every sweep below reuses that one file as its B=0 normaliser, so if this control disagrees, the
shared normalisation is invalid and I need to know before drawing conclusions from any of it.

## Set C — BLEND sweep × GRUNT and ATTACK (12 files)

**Stimulus: `test_signal_48k.wav`.**

These turn the pedal's own switches into localisers. ATTACK reroutes C8 inside the treble network —
the OD path's one genuine two-path cancellation, and my leading structural suspect. GRUNT changes
the clipper's input coupling. If the excess phase moves with ATTACK, the carrier is in the treble
ladder; if it moves with GRUNT, it's at the clipper input. That's localisation from hardware rather
than from a fit.

## Set D — LEVEL sweep at DRIVE min (3 files)

**Stimulus: `test_signal_48k.wav`.** DRIVE fully CCW, BLEND max, LEVEL as listed.

At drive-min the chain is ~linear, and the LEVEL pot moves the OD gain and the clean bleed by

## Protocol

Same as the existing matrix (`docs/validation-and-capture.md` §3) — nothing new. The ones that have
actually bitten this project:

1. **Same interface send AND record gain as the original 0 dB session.** Files without a `gain-`
   token are all at that session's gain; if the gain moves, the file needs a `gain-n<dB>` token or
   it silently mis-fits. Don't change it partway through a set.
2. **Watch for clipping.** Session 24 lost 14 takes pinned at peak 0.98850. `drive-1700_blend-1430`
   is the hottest file here. If anything pins, drop the interface input gain 12 dB, re-take the
   whole affected set, and add the `gain-n12` token.
3. **Full length, no truncation** — a short file's missing segments read as zeros and produce
   confident nonsense. Main stimulus is ~127 s, tone stimulus is 103.3 s.
4. **One thing changed at a time** from the reference table. Return every other control to
   reference between blocks rather than working from wherever the last file left them.
5. **Drop them in `analysis/captures/`** with exactly the filenames above (lowercase, single
   hyphens). They're gitignored, so please keep your own backup.
6. If a take feels wrong, re-take it rather than noting it — a bad take that reaches the analysis
   costs a whole session to localise (sessions 8, 24, 48 each lost time to one).
